# Languages

The game is written in English and translated at the moment a word reaches
the screen. Nothing in the data files changes for a new language.

## How it works

- `js/i18n.js` defines `CF.T(string, vars)`. The UI (`js/ui.js`,
  `js/screens.js`, `js/main.js`) passes every label, description, story and
  tooltip through it, and the static text of `index.html` is walked once per
  language change.
- A language is a dictionary `{ 'English string': 'translation' }` loaded
  with `CF.addStrings('ar', {...})` from `js/lang/<code>/*.js`. Keys are
  the exact English strings in the data and code.
- A key with `{placeholders}` is a template: `'Witness: {name}'` matches
  every witness card, and the captured part is translated on its own (a
  name is transliterated word by word from the names in the dictionary).
- A string no key matches is tried sentence by sentence, then as a list
  (`', '`, `' · '`, `' / '`), then as a run of known words. Digits and times
  pass through untouched.
- The player picks the language on the title screen or in Settings
  (`lang`), and `CF.setLang` flips the page's `dir` and `lang` attributes;
  `css/style.css` restyles under `[dir=rtl]` (Amiri, no letter-spacing).

## Adding or updating text

Write the English in the data or code as before, then give it an Arabic
entry. `node tools/i18n_extract.js --missing ar` lists every string that has
none, by source file, and `tests/i18n.test.js` (part of `npm test`) fails
until the list is empty and a bot-played game reads fully in Arabic. A
string built from pieces at runtime (`'Guilty: ' + name`) needs a template
key (`'Guilty: {name}'`) in the file for its source.

The extractor sets aside literals that look like pieces of such strings:
markup, leading punctuation, and anything that starts lowercase ('the lane
behind the Red Ox'). A lowercase literal of three words or more that ends
on a stop is a sentence the player reads ('or drop a card on the token.
...'), so it is kept as a key and checked like the rest.

## House terms

`docs/GLOSSARY.md` fixes how the city's words are rendered in Arabic (the
Examiner is المحقق, never the coroner's الفاحص; one spelling of
دومينيكيّ). Its last section, *Checked in every entry*, is read by
`tests/i18n.test.js`: any entry whose English names one of those terms
must carry its Arabic stem. A preposition joins the word it governs
(أجب ب{card} gives بالفطنة), with no tatweel before the article.

## Adding a language

1. Add its code to `CF.LANGS` in `js/i18n.js` with a name and direction.
2. Create `js/lang/<code>/` with files in the shape of `js/lang/ar/`.
3. List the files in `index.html` (after `js/i18n.js`) and in `sw.js`.
4. Add an option to the `#s-lang` select in `index.html`.
5. `npm test` checks the coverage.
